# RAG 语料使用建议：清洗、切分、标注与评测

> 适用：把本语料包接入知识库/问答系统/微调数据集
> 关键词：RAG、文本切分、元数据、问答对合成、评测集

## 1. 入库前清洗

| 问题 | 处理方式 |
|---|---|
| 网页导航、页脚、版权声明 | 正则删除固定模板段（"版权所有""京ICP备""扫一扫"） |
| PDF 页眉页脚、页码 | 按行删除重复出现的短行 |
| 表格错位 | 转为 Markdown 表格；跨页表格合并表头 |
| 中文断行 | 合并段内换行，保留段落间空行 |
| 全角/半角混排 | 数字与英文统一半角，标点保留中文全角 |
| 图片中的文字 | OCR 后人工抽检 5%，错字率 >2% 的整段弃用 |
| 重复内容 | 按 SimHash 去重，阈值 0.9 |

## 2. 切分策略

### 2.1 分层切分（推荐）

本语料包天然带标题层级，优先按结构切：

```
文档 → 一级标题（章） → 二级标题（节） → 段落块
```

- **chunk 大小**：512–1024 tokens（中文约 400–800 字）；
- **overlap**：10–15%，即 60–120 tokens；
- **不切断表格**：一个表格必须完整落在同一 chunk；
- **不切断列表**：编号列表整块保留；
- **保留标题路径**：每个 chunk 前置 `标题路径`，例如 `BLM > 战略部分 > 市场洞察`。

### 2.2 切分参数速查

| 文档类型 | chunk | overlap | 说明 |
|---|---|---|---|
| 方法论（01–05） | 600–800 tokens | 15% | 概念密度高，宁可小 |
| 宏观政策（06） | 800–1000 tokens | 10% | 长段落多，按条目切 |
| 行业研究（07） | 600 tokens | 10% | 表格多，按小节切 |
| FAQ/问答对 | 单条 | 0 | 一问一答一 chunk |

### 2.3 反模式

- 按固定字数硬切，把一句话切成两半；
- 把整篇 8000 字文档塞进一个 chunk（检索精度骤降）；
- 把表格拆散（模型读到半张表会编造）；
- 丢掉标题（chunk 失去上下文，召回后无法判断主题）。

## 3. 元数据设计

每个 chunk 建议带以下字段：

```json
{
  "doc_id": "BLM-002",
  "title": "BLM 业务领先模型",
  "category": "methodology",
  "sub_category": "BLM",
  "org": "原创综述",
  "year": 2026,
  "section_path": "BLM > 战略部分 > 市场洞察",
  "chunk_index": 12,
  "source_url": "https://wiki.mbalib.com/wiki/业务领先模型",
  "license": "原创/引用公开概念",
  "lang": "zh",
  "char_count": 742,
  "keywords": ["市场洞察", "五看", "价值转移"]
}
```

字段用途：
- `category` / `sub_category`：检索时做**元数据过滤**，避免"问 BLM 召回 BSC"；
- `section_path`：拼进 chunk 正文，提升上下文完整性；
- `year`：政策与数据类必须按年份过滤，避免用旧数据回答新问题；
- `source_url`：生成答案时给出引用，便于人工核验。

## 4. 问答对合成（用于评测与微调）

每个框架至少合成四类问题：

| 类型 | 示例 | 考查点 |
|---|---|---|
| 概念定义 | BLM 的八要素是什么？ | 召回完整性 |
| 要素关系 | 业绩差距和机会差距有什么区别？ | 辨析能力 |
| 操作步骤 | 战略地图怎么画？分几步？ | 流程理解 |
| 场景应用 | 一家制造企业想从代工转品牌，用 BLM 该怎么分析？ | 迁移能力 |

合成方法：
1. 从每个二级标题生成 2–3 个问题；
2. 用 LLM 基于 chunk 生成答案，**必须带原文引用**；
3. 人工抽检 20%，重点看是否有"编造细节"；
4. 把"答案不在语料中"的问题也放进去（各 10%），测试拒答能力。

建议规模：本语料包 10 篇文档，可合成 300–500 条问答对，其中 50 条作为固定评测集。

## 5. 检索质量优化

| 手段 | 做法 | 收益 |
|---|---|---|
| 混合检索 | BM25 + 向量，RRF 融合 | 中文专有名词（BLM、DSTE）靠 BM25，语义靠向量 |
| 查询改写 | 把"华为怎么定战略"改写成"华为 DSTE 战略规划流程" | 提升召回 |
| 父子块 | 子块检索，父块（整节）喂给模型 | 兼顾精度与上下文 |
| 重排序 | bge-reranker 等中文 rerank 模型 | 提升 top-3 命中率 |
| 元数据过滤 | 按 category/year 先筛后检 | 减少跨主题串扰 |
| 引用回填 | 答案附 `source_url` + `section_path` | 可核验，降低幻觉 |

## 6. 评测集设计

最小可用评测集包含 50 题，分布建议：

| 维度 | 题量 | 说明 |
|---|---|---|
| 单文档事实 | 20 | 答案在单一 chunk 内 |
| 跨文档综合 | 15 | 需要合并 2–3 个 chunk |
| 计算/推理 | 5 | 如 TAM/SAM/SOM 测算 |
| 拒答 | 5 | 语料中没有答案 |
| 时效性 | 5 | 需按年份过滤（如"十五五"目标） |

指标：Recall@5、MRR、答案正确率（人工 1–5 分）、引用准确率、拒答准确率。

## 7. 版权与合规

- 国家机关文件（规划建议、政府工作报告、统计公报）可自由使用；
- 咨询机构报告仅作内部研究，不对外分发原文；
- 百科内容引用需注明来源；
- 若做对外产品，建议以**原创综述 + 公开政策文本**为主体，商业报告只做检索出处，不复制正文。

## 8. 快速接入清单

1. 把 `01`–`07` 转成纯文本（去掉 Markdown 标记，保留标题层级）；
2. 按 `##` 二级标题切分，再按 800 字合并/拆分；
3. 生成元数据表（Excel 或 JSON）；
4. 入向量库，同时建 BM25 索引；
5. 跑 20 条冒烟问题，检查召回；
6. 合成 300 条问答对，抽检 20%；
7. 上线后收集 badcase，按月补语料。
